# 공모주 위험 신호 달력 + 스마트폰 알림 — 설계 문서

작성일: 2026-11-17 · 상태: 승인 대기

## 1. 왜 만드는가

사용자는 피너츠 앱에서 일정만 보고 한국투자증권으로 넥스아이를 청약했고, 상장 첫날 공모가(8,000원) 대비 약 40% 하락을 겪었다. 그런데 청약 전에 이미 공개된 숫자가 위험을 가리키고 있었다.

| 신호 | 넥스아이 수치 |
|---|---|
| 확정 공모가 | 희망 범위(10,500~13,000원) 하단보다 23.8% 낮은 8,000원 |
| 의무보유확약 | 0.06% |
| 기관 경쟁률 | 66.58대 1 |
| 수요예측 가격 분포 | 신청 수량의 48.15%가 하단 미만 가격 제시 |
| 상장일 유통가능물량 | 약 37% |

일정 앱은 이 숫자들을 "위험하다"로 묶어 알려주지 않았다. 이 프로젝트는 그 일을 대신한다.

## 2. 목표 / 하지 않는 것 / 실패로 보는 것

**목표**
- 청약 마감 전에, 사용자가 찾아보지 않아도 스마트폰으로 위험 신호 요약이 온다.
- 스마트폰에서 달력 형태로 청약 일정을 보고, 종목을 누르면 상세 숫자를 본다.
- 위험 기준이 감이 아니라 과거 상장 성적으로 검증돼 있다.
- 비슷했던 과거 공모주의 첫날 성적과 예측 모델로, 이번 종목의 첫날 종가 범위를 보여준다(4.4).

**하지 않는 것**
- 청약·매수·매도 추천, 자동 청약
- 상장 이후 주가 추적, 수익률 관리, 첫날 이후 시점(며칠~한 달 뒤)의 가격 예측
- 로그인, 여러 사용자 지원
- 앱스토어에 올리는 네이티브 앱

**실패로 보는 것 (동작해도 실패)**
- 수집이 깨졌는데 조용히 넘어가서, 알림이 없는 것을 "안전하다"로 오해하게 만드는 것
- 위험 신호 표시를 "청약하지 마라/해라"로 읽히게 쓰는 것

## 3. 사용자가 보게 되는 것

### 3.1 웹앱 (스마트폰 홈 화면에 추가)

```
        2026년 11월              ◀ ▶
 월    화    수       목       금
 16    17    18       19       20
             유캐스트 ⚠3 ────▶
             에스에프씨 ──────▶
 23    24    25       26       27
 아델 ────▶                    에이엔에이치 ─▶
       케이엠에프 ────▶

마지막 갱신: 11/17 18:02
```

- 월 단위 달력. 청약 기간이 막대로 표시되고, 위험 신호 개수가 종목명 옆에 붙는다.
- 종목을 누르면 상세가 펼쳐진다: 청약일, 상장일, 주간 증권사, 신호별 수치와 ⚠ 여부, 38커뮤니케이션 원문 링크.
- 수요예측 결과가 아직 없는 종목은 "대기 중"으로 표시한다.
- 스팩(SPAC)은 달력에 표시하되 위험 점수는 매기지 않는다("스팩" 표시).
- 화면 아래에 "마지막 갱신 시각"과 "투자 권유가 아닌 정보 정리"라는 안내를 항상 보여준다.
- 좁은 화면(스마트폰)에서는 달력 아래에 날짜순 목록을 함께 보여준다.
- **디자인은 사용자가 제공한 `C:\공모주\DESIGN.md`(토스 TDS Mobile)를 기준으로 한다.** 그 파일의 색·글꼴·글자 크기·간격·버튼 규격을 그대로 쓰고, 파일에 없는 달력·막대·상세 패널은 같은 토큰으로 조합한 "확장"으로 만든다. 자세한 규칙은 구현 계획의 Global Constraints에 있다.

### 3.2 스마트폰 알림 (ntfy 앱)

- **수요예측 결과가 처음 잡힌 때**: `유캐스트 ⚠3개 · 청약 11/18~19` + 본문에 신호별 수치
- **청약 시작 전날 저녁**: 같은 내용을 한 번 더
- 위험 신호가 0개인 종목도 알림을 보낸다(`⚠0개`). 알림이 없는 것과 안전한 것을 구분하기 위해서다.
- 알림을 누르면 웹앱의 해당 종목이 열린다.
- **수집 실패 알림**: 수집이나 해석이 실패하면 "오늘 수집 실패" 알림을 보낸다.

## 4. 만드는 방법

### 4.1 검토한 방법

| 방법 | 장점 | 단점 |
|---|---|---|
| A. Claude 예약 작업이 매일 검색해서 알림 | 가장 빨리 써볼 수 있음 | 숫자가 출처마다 흔들림, 달력 화면 없음, 컴퓨터가 켜져 있어야 함 |
| B. 컴퓨터에서 도는 프로그램 + 컴퓨터 화면 | 설정이 적음 | 스마트폰에서 달력을 볼 수 없음, 컴퓨터가 꺼지면 멈춤 |
| **C. 인터넷에 올린 웹앱 + 클라우드 자동 실행 (선택)** | 스마트폰에서 달력 확인, 컴퓨터가 꺼져도 동작, 무료 | GitHub 계정과 초기 설정 필요 |

사용자가 "스마트폰 앱 기준(또는 웹앱)"을 골랐으므로 C로 간다. 네이티브 앱이 아닌 웹앱인 이유는 앱스토어 등록과 개발자 계정 없이 홈 화면에 추가해 앱처럼 쓸 수 있기 때문이다.

### 4.2 구성 (아래는 사용자가 맡긴 부분에 대한 작성자의 선택)

```
GitHub Actions (하루 2회, 08:00 / 18:00 KST)
  └ Python 수집기: 38커뮤니케이션 표 3종 + 종목 상세 페이지
      └ 점수 계산 → data/ipos.json 갱신 → 저장소에 커밋
      └ 새 결과·전날 알림 판정 → ntfy로 푸시
GitHub Pages
  └ 정적 웹앱(HTML/CSS/JS, 프레임워크 없음)이 ipos.json을 읽어 달력 표시
```

- **데이터 출처**: 38커뮤니케이션 (2026-11-17에 내용 확인함)
  - 청약 일정: `/html/fund/index.htm?o=k`
  - 수요예측 결과(기관 경쟁률, 확약, 확정가): `?o=r1`
  - 신규상장(시초가, 첫날 종가): `?o=nw`
  - 종목 상세(가격 분포, 확약 기간별 수량, 유통가능물량 표): `/html/fund/?o=v&no=<번호>`
- **수집 예절**: 하루 2회, 요청 사이 1초 이상 간격, 변경 없는 상세 페이지는 다시 받지 않는다.
- **알림 중복 방지**: 보낸 알림 기록을 `data/state.json`에 저장한다.
- **비밀값**: ntfy 채널 이름은 GitHub Secrets에 둔다. 저장소와 웹앱 주소는 공개지만 담기는 내용은 공개된 공모주 정보뿐이다. (무료 GitHub Pages는 공개 저장소에서만 동작하므로 저장소는 공개로 만든다. 작성자의 선택.)
- **알림의 웹앱 링크**: ntfy 알림의 클릭 주소를 `https://<계정>.github.io/<저장소>/#<종목번호>`로 넣고, 웹앱은 주소 끝의 종목번호를 읽어 해당 종목 상세를 연다.
- **시간대**: GitHub Actions 예약은 UTC 기준이므로 KST 08:00/18:00을 UTC 23:00(전날)/09:00으로 등록한다. "청약 시작 전날" 판정은 KST 날짜로 한다.
- **데이터가 쌓이는 범위**: 달력에는 지난 3개월~앞으로의 청약을 담는다. 그보다 오래된 종목은 백테스트용 파일(`data/history.json`)에만 남긴다.
- **언어**: 수집·점수는 Python(requests, BeautifulSoup), 화면은 순수 HTML/JS.

### 4.3 위험 신호와 기준

초기 기준은 작성자의 제안이며 검증 전이다.

| 신호 | 초기 기준(⚠) |
|---|---|
| 확정 공모가 위치 | 희망 범위 하단 이하 |
| 기관 경쟁률 | 300대 1 미만 |
| 의무보유확약 비율 | 5% 미만 |
| 하단 미만 가격 신청 비율 | 20% 이상 |
| 상장일 유통가능물량 | 35% 이상 |
| 최근 시장 분위기 | 최근 상장 10종목(스팩 제외) 중 절반 이상이 첫날 종가가 공모가 아래 |

**기준 검증(백테스트)**: 과거 종목들의 수요예측 결과와 신규상장 성적을 모아, 신호 개수별로 "첫날 종가가 공모가 아래였던 비율"을 표로 낸다. 이 결과를 보고 기준을 조정하고, 결과 표는 저장소에 남긴다. 기준값은 설정 파일 하나에 모아 쉽게 바꿀 수 있게 한다.

**반드시 통과해야 하는 확인**: 저장해 둔 넥스아이 페이지로 돌렸을 때 위험 신호가 4개 이상 나와야 한다. 반대로 최근 첫날 성적이 좋았던 종목(예: 옵토닉스, 확약 5.62%·경쟁률 1201대 1·공모가 상단 확정)은 신호가 1개 이하여야 한다.

**값이 없을 때**: 확약 비율이 "-"로 비어 있는 등 값이 없는 신호는 ⚠로 세지 않고 "확인 불가"로 표시한다. 알림 본문에 "확인 불가 N개"를 함께 적는다.

### 4.4 첫날 가격 예측 (2026-11-17 추가)

사용자는 공모주를 **상장 첫날** 판다. 그래서 예측 대상은 **첫날 종가의 공모가 대비 등락률**이다. 사용자가 두 방식을 모두 원했다.

**데이터**: 38커뮤니케이션 신규상장 표에 2023년 5월 이후 약 380종목(스팩 제외 약 300종목)의 시초가·첫날 종가가 있다. 각 종목의 상세 페이지에서 신호 값을 함께 모아 `data/history.json`에 둔다. 최초 1회 대량 수집(요청 간 1초 이상), 이후에는 새로 상장한 종목만 추가한다.

**비교에 쓰는 값(작성자의 선택)**: 기관 경쟁률(로그), 의무보유확약 %, 희망 범위 안에서 확정 공모가의 위치, 하단 미만 신청 비율, 유통가능물량 %, 최근 시장 분위기, 공모금액(로그), 시장(코스닥/유가증권), 바이오 업종 여부. 값이 없는 항목은 비교에서 빼고 계산한다.

**방식 1 — 비슷한 종목 비교**
- 위 값들을 같은 척도로 맞춘 뒤, 이번 종목과 가장 가까운 과거 종목 10개를 고른다.
- 보여주는 것: 10개의 첫날 등락률 가운데 값, 대부분이 들어가는 범위(25~75%), 공모가 아래로 끝난 개수, 이를 원 단위로 바꾼 예상 범위, 비슷한 종목 목록(이름·첫날 등락률·원문 링크).

**방식 2 — 예측 모델**
- 같은 값으로 첫날 등락률을 예측하는 단순한 모델을 쓴다(규제를 건 선형 회귀 수준. 데이터가 300개라 복잡한 모델은 과적합 위험이 크다. 작성자의 선택).
- 숫자 하나와 함께 오차 범위(과거 검증에서 나온 평균 오차)를 항상 같이 보여준다. 숫자만 단독으로 표시하지 않는다.

**공통 규칙**
- 첫날 가격은 공모가의 60%~400% 범위로 제한되므로 예측값도 그 안으로 자른다.
- **정확도 검증**: 시간 순서로 나눠(앞의 데이터로 배우고 뒤의 종목으로 채점) 두 방식의 평균 오차와 "공모가 위/아래" 적중률을 잰다. 비교 기준은 "모든 과거 종목의 가운데 값"을 그냥 답하는 경우다.
- **기준보다 못하면 숨긴다**: 어떤 방식이 비교 기준보다 정확하지 않으면 그 방식의 결과는 화면과 알림에 내보내지 않고, 이유를 검증 결과 표에 남긴다.
- 화면에 "과거 정확도: 위/아래 적중 N%, 평균 오차 ±M%p"를 함께 표시한다.
- 수요예측 결과가 나오기 전 종목은 예측하지 않는다("대기 중").

**보이는 곳**
- 종목 상세 화면에 "비슷했던 과거 공모주" 영역과 "모델 예측" 영역을 나란히 둔다.
- 알림 본문에 한 줄 추가: `비슷한 10개 중 7개 하락 · 모델 예측 -9% (±18%p)`

## 5. 위험 요소

1. **클라우드에서 38커뮤니케이션 접속이 막힐 수 있다.** GitHub Actions는 해외 서버에서 돈다. 구현 첫 단계에서 접속부터 확인한다. 막히면 수집만 사용자 컴퓨터(윈도우 예약 실행)에서 돌리고 결과를 저장소에 올리는 방식으로 바꾼다. 이 경우 컴퓨터가 꺼져 있으면 갱신이 멈춘다.
2. **사이트 구조가 바뀌면 수집이 깨진다.** 표에서 0건이 나오거나 필수 값이 비면 실패로 처리하고 실패 알림을 보낸다.
3. **사이트 숫자에 입력 오류가 있을 수 있다**(사이트가 직접 밝힘). 상세 화면에 원문 링크를 둔다.
4. **유통가능물량 표는 종목마다 형태가 다를 수 있다.** 해석에 실패하면 그 신호만 "확인 불가"로 표시하고 나머지는 정상 표시한다.
5. **기준이 틀릴 수 있다.** 신호는 확률적 참고일 뿐이라는 안내를 화면과 알림에 넣는다.
6. **예측이 확실해 보이는 것.** 300종목으로 배운 예측은 오차가 크다. 숫자는 항상 오차 범위와 과거 정확도와 함께만 보여준다. 시장 분위기가 과거와 크게 다르면(예: 급락장) 과거 패턴이 맞지 않을 수 있다.
7. **과거 상세 페이지 형식 차이.** 2023년 종목은 상세 페이지 형식이 다를 수 있다. 해석 실패 항목은 비워 두고 비교에서 뺀다.

## 6. 사용자가 한 번 해야 하는 일

1. GitHub 계정 준비(없으면 가입)와 저장소 생성 승인
2. 스마트폰에 ntfy 앱 설치 후 채널 구독
3. 스마트폰 브라우저에서 웹앱을 홈 화면에 추가

비밀번호와 인증 코드 입력은 사용자가 직접 한다.

## 7. 만드는 사람에게 맡기는 것

- 달력의 세부 디자인(색, 글꼴, 막대 모양)
- 파일·폴더 구조, 테스트 도구 선택
- 페이지 인코딩 처리(EUC-KR 가능성 확인)
- 예측 모델의 세부 형태와 비교 값의 가중치(단, 4.4의 "단순한 모델" 원칙과 검증 규칙은 지킨다)

## 8. 테스트

- 저장한 HTML 견본으로 수집기 해석 테스트(일정, 수요예측, 신규상장, 상세)
- 점수 계산 단위 테스트(경계값 포함)
- 넥스아이 견본 통과 확인(4.3)
- 알림 중복 방지와 전날 알림 판정 테스트
- 수집 실패 시 실패 알림이 나가는지 테스트
- 예측: 60%~400% 범위 자르기, 값 없는 항목 처리, 비교 기준보다 못한 방식이 숨겨지는지 테스트
- 예측: 검증 결과 표(방식별 평균 오차, 위/아래 적중률)가 저장소에 생성되는지 확인
