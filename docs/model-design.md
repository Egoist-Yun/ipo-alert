# 공모주 하락 경고 모델 설계도 (2026-11-18)

외부 설계도(「공모주 시초가·첫날 종가 예측 모델 설계도」)를 현재 모델과 비교하고, 실험으로 확인한 개선안을 반영한 설계다. 실험 재현은 `scripts/model_experiments.py`.

## 1. 목적과 비목표

- 목적: 청약 전·후에 "공모가 아래로 떨어질 가능성"을 미리 알리고, 경고가 실제로 얼마나 맞았는지 개수로 보여준다.
- 사용자 행동: 상장일 장 시작 직후 매도. 그래서 시초가 하락이 목표 지표다. 다만 시초가 하락 모델(AUC 0.965)은 일반청약 경쟁률이 필요해 **청약 결정 뒤에만** 쓸 수 있으므로 "청약 마감 후 참고"로 둔다. **대표 지표는 청약 전 모델**(종가 하락 AUC 0.88)이고, 청약 전에 쓸 수 있는 시초가 하락 모델이 다음 과제다.
- 비목표: 정확한 가격 예측(오차 ±41~62%p로 신뢰 불가), 투자 자문, 서버/API 서비스화.

## 2. 현재 모델

| 구성 | 내용 |
|---|---|
| 신호 6개 | 공모가 위치, 기관 경쟁률, 의무보유확약, 하단 미만 신청, 유통가능물량, 시장 분위기 |
| 청약 전 모델 | 로지스틱, P(종가<공모가). 2023-05 이후 학습. 변수 5개(lockup, offer_amt, kospi, mcap, bio) |
| 청약 후 모델 | 로지스틱, P(시초가<공모가). 2015+ 881개로 학습, 일반청약 경쟁률 추가 |
| 가격 예측 | kNN(k=10) + 로그수익률 릿지 평균 |
| 경고 기준 | 검증 구간에서 하락의 70% 이상 잡는 가장 높은 문턱(0.05 격자). 시험 구간은 확인만 |
| 강한 경고 | 모델 경고 + 같은 조건의 과거 하락 패턴 일치 |
| 검증 | 시간 순서(walk-forward), 검증 57개 / 시험 81개(2025-08 ~ 2026-11) |

## 3. 외부 설계도와의 차이

| 항목 | 외부 설계도 | 현재 |
|---|---|---|
| 모델 | LightGBM + 단조 제약 | 선형 + kNN (표본 300개 규모에는 선형이 안전) |
| 타깃 | 시초가 회귀, 하락, 따따블, 종가(시초가 대비) | 시초가·종가 가격, 시초가 하락, 종가 하락 |
| 출력 | 확률 + 10/50/90% 분위수 | 확률 + (이번 작업에서 추가) 가격 범위 |
| 시장 변수 | 코스닥 20일 수익률 등 | 최근 상장 10개의 하락 비율과 열기 |
| 검증 | AUC, Brier, 부트스트랩, 상승/하락장 분리, 매매 시뮬레이션 | 재현율/정밀도, 시험 구간 분리 (+ 이번 작업에서 AUC·시뮬레이션·시장 분리 실측) |
| 데이터 | DART + KRX | 38커뮤니케이션 |

## 4. 실험 결과와 결정 (시험 구간 81개, 하락 사례는 12~18개뿐이라 수치가 흔들림)

| 아이디어 | 결과 | 결정 |
|---|---|---|
| 2015+ 대 2023+ 학습 (시초가 모델) | AUC 0.965 대 0.961, 포착 10/12 대 9/12 | **2015+ 유지** (차이는 종목 1개) |
| 코스닥 20일 수익률 변수 | 시초가 AUC 0.965→0.964, 종가 0.881→0.871 | **기각** (개선 없음) |
| 시간 감쇠 가중치 | 검증 AUC은 오르지만(0.893→0.92) 시험 AUC은 내림(0.965→0.95) | **기각** (시험 구간이 확인하지 못함) |
| 하락장 성능 | 코스닥 20일 수익률 < 0인 29개: 시초가 하락 6/6 포착, 종가 하락 7/11 포착. 상승장 52개: 4/6, 3/7 | **하락장에서 무너지지 않음.** 하락장은 종가 하락 비율이 38%(상승장 13%)라 시장 분위기 변수는 유지 |
| 매매 시뮬레이션 | 시초가 매도: 경고 종목 16개의 평균 +7%, 중앙값 -4%. 종가 보유: 15개 평균 -6%, 중앙값 -25% | 경고는 **가운데 값 기준 손실 회피**에는 도움. 총수익을 키운다고 말하면 안 됨(경고 종목 중 대박도 있어 평균은 양수) |
| 가격 분위수 구간 | 80% 목표인데 시험 구간 포함률 70~83%, 폭이 +100%p 안팎 | **표시하되** 과거 적중률을 함께 보여줌 |
| LightGBM, DART 파싱, M3·M4, 서버/API | 표본 대비 이득 불확실 | **보류** |

## 5. 개선 설계

### 5-1. 구현됨 (미커밋, 테스트 통과)
1. **경고 근거를 개수로 표시:** "경고 16개 중 10개 적중 · 하락 12개 중 10개 포착". 12개 중 10개를 83%로 표시하던 것을 바꿈.
2. **가격 범위 표시:** 시초가/종가 예상 옆에 10~90% 범위와 "과거 N% 적중".
3. **새 제도 표시: 보류(코드 제거).** 2026-11-13 제도 변경(사전수요예측, 코너스톤 6~10개월 보유)은 실제로 있었다(SBS Biz, 토스뱅크 기사). 그러나 사전수요예측은 증권신고서 제출 전 단계라, 청약일 기준으로 표시하면 이미 진행 중이던 옛 제도 종목(제논, 태석광학 등)이 잘못 표시된다. 기준을 증권신고서 제출일 또는 코너스톤 배정 여부로 정할 수 있는지 확인되기 전까지 표시하지 않는다.
4. **화면 문구:** 청약 후 모델은 "청약 마감 후 참고", 경고는 "손실을 피하기 위한 용도이며 건너뛴다고 평균 수익이 오르는 건 아니다"(경고 종목도 시초가 매도 평균 +7%)를 표시한다.
5. **모델 캐시 재생성:** 새 형식(개수, 범위)이 없는 `data/model.json`은 자동으로 다시 만든다.

### 5-2. 다음 설계 (아직 안 만듦, 이 순서)
1. **예측 기록부:** 상장 전에 예측(확률, 경고 여부)을 저장하고 상장 후 결과와 대조한다. 11/18 이후 상장 종목부터 새로 채점한다. 드리프트 감시는 경보 대신 "최근 N개: 경고 몇 개, 실제 하락 몇 개"를 개수로 보여준다(10개 창은 하락이 1~2개라 비율이 잡음).
2. **확약 기간 변수:** 38 상세 페이지에 기간별 확약 표가 있다(예: 넥스아이 "3개월 확약 7,000 / 15일 확약 155,000"). 2025 이전은 없을 수 있어 커버리지를 먼저 확인하고, 가중평균 확약 기간을 후보 변수로 시험한다.
3. **청약 전 시초가 하락 모델:** 일반청약 경쟁률 없이 쓸 수 있는 시초가 하락 확률을 대표 지표로 올린다.
4. **매매 시뮬레이션 상시 보고:** 경고 건너뛰기 전후의 중앙값과 최악 손실을 `data/backtest.md`에 갱신.
5. **하락장/상승장 분리 성적:** 코스닥 지수는 보고용 구분으로만 쓴다.
6. **새 제도 재검증:** 구별 기준이 정해지고 표본이 20~30개 쌓이면 그 표본으로 다시 잰다.

## 6. 검증 규칙 (바꾸지 않는다)
- 시간 순서 검증만 쓴다. 대상 종목의 청약 시작일 이전 데이터만 학습에 쓴다.
- 변수와 문턱은 검증 구간으로 정하고, 시험 구간은 마지막에만 본다.
- 성능은 "하락을 몇 개 잡았나 / 경고가 몇 번 맞았나"로 말한다(대부분 오르므로 위/아래 적중률은 의미 없음).
- 새 변수는 검증과 시험 **둘 다**에서 개선될 때만 채택한다.
- **시험 구간(81개, 2025-08 ~ 2026-11)은 이미 사용됨.** 2015+/2023+, 코스닥 변수, 시간 감쇠, 하락장 분리 비교에 여러 번 썼으므로 이 구간의 점수는 낙관적이다. 모델을 고정하고, 2026-11-18 이후 상장 종목은 예측 기록부로 새로 채점한다.

## 7. 한계
- 하락 사례가 시험 구간에 12~18개뿐이라 모든 경고 수치의 신뢰구간이 넓다.
- 가격 예측은 오차가 커서 참고용이다. 경고(확률)가 주 기능이다.
- 새 제도 종목은 검증이 부족하다.
- 상장 당일 지수 급변, 테마 열풍 같은 숫자로 잡기 어려운 요인은 반영하지 못한다.
- 코스닥 지수 데이터는 Yahoo 비공식 API로 받았다. 상시 파이프라인에 넣지 않은 이유다.

## 8. 열린 질문
1. 새 제도 종목을 38 데이터로 구별할 수 있는가(증권신고서 제출일, 코너스톤 배정 여부)
2. 경고의 목적을 "가운데 값 기준 손실 회피"와 "평균 수익" 중 무엇으로 할지(문턱이 달라진다, 사용자 결정 필요)
3. 2023-06 가격 제한 변경(시초가 90~200% → 60~400%) 전후로 확률 보정이 맞는지(구간별 Brier)
4. 마감 전 실시간 경쟁률로 청약 후 모델을 쓸 수 있는지(미검증)
5. 외부 설계도의 M3·M4 정의와 원문이 저장소에 없어 재현성이 떨어짐
